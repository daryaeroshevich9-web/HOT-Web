📄 Сборка JSON-файла для новой противообледенительной жидкости

Инструкция для сотрудника, который получает таблицу HOT (Holdover Time) и должен создать единый JSON-файл для веб-приложения.

Цель

Создать один JSON-файл, содержащий все данные для расчёта времени защитного действия (HOT) для конкретной жидкости. Файл используется веб-приложением для вычисления HOT на основе погодных условий (METAR).

Важно: Все 5 полей обязательно должны присутствовать, даже если они пустые ([] или {}).

Структура итогового JSON

{
  "temperature_bands": [ ... ],
  "table": [ ... ],
  "event_index": [ ... ],
  "event_index_rules": [ ... ],
  "rules": [ ... ]
}

1. temperature_bands – диапазоны температур

Задаёт, для каких температур (OAT) есть данные. Каждый диапазон соответствует строке таблицы.

Формат Массив объектов:

[
  { "min_inclusive": -3, "max_exclusive": 100 },
  { "min_inclusive": -8, "max_exclusive": -3 },
  ...
]
  • min_inclusive – нижняя граница (включительно).
  • max_exclusive – верхняя граница (не включается).
  • Диапазоны идут по возрастанию температуры.
  • Последний диапазон часто имеет "max_exclusive": -100 (или другое очень низкое значение).

2. table – таблица HOT

Двумерный массив: строки = температурные диапазоны, столбцы = группы событий.

Формат Каждая ячейка – объект с ключами концентраций:

{
  "100/0": "0:15 - 0:30",
  "75/25": "0:10 - 0:20",
  "50/50": "0:05 - 0:10"
}
  • Количество строк = temperature_bands.length.
  • Строки могут иметь разную длину (если для некоторых столбцов нет данных при низких температурах).
  • Если значения нет – ставьте null.
  • Время пишется в формате "ЧЧ:ММ - ЧЧ:ММ" (диапазон) или "ЧЧ:ММ" (конкретное).
  • Допустимы пояснения: "0:15 - 2:00 if Cold-Soaked Wing".

3. event_index – группы событий

Определяет, какой столбец таблицы соответствует какому набору METAR-кодов.

Формат Массив массивов строк:

[
  ["FZFG", "FZBR", "IC"],
  ["-SN", "-SG"],
  ["SN", "SG"],
  ...
]
  • Порядок групп важен: группа с индексом 0 → столбец 0, индекс 1 → столбец 1 и т.д.
  • Если событие входит в несколько групп, берётся первая подходящая (если нет правил переопределения).
  • Если у вас нет чётких групп, скопируйте из похожего типа (например, из type_i.json).

4. event_index_rules – правила переопределения индекса события

Применяются до поиска по event_index. Могут сразу вернуть результат (предупреждение) или задать конкретный индекс столбца.

Формат Массив объектов:

{
  "id": "br_freezing",
  "description": "BR at OAT ≤ 0 → FZBR column",
  "priority": 2,
  "when": { "events_list_has_any": ["BR"], "temp_lte": 0 },
  "then": { "event_index_override": 0 }
}
  • priority – чем меньше число, тем выше приоритет. Если несколько правил подходят, сработает правило с наименьшим приоритетом.
  • when – условия:
    • temp_lt, temp_lte, temp_gt, temp_gte – сравнение температуры.
    • intensity_eq, intensity_in – интенсивность осадков.
    • event_index_eq, event_index_in – проверка текущего индекса.
    • note_6, snowfall, heavy_snowfall, light_snowfall, has_ice_pellets, snowfall_and_obscuration – булевы флаги контекста.
    • events_list_has_any – есть ли хотя бы одно событие из списка.
    • events_list_eq – точное совпадение списка событий.
  • then – действие:
    • "result": "текст" – сразу вернуть это значение (HOT или предупреждение).
    • "event_index_override": число – использовать указанный индекс столбца.
Совет: Если особых правил нет, оставьте [].

5. rules – финальные корректирующие правила

Применяются после того, как определены индексы. Могут переопределить HOT или изменить индекс.

Формат и условия такие же, как в event_index_rules. Обычно здесь:

  • Ограничения по температуре (например, при temp < -25 → предупреждение).
  • Выбор столбца в зависимости от интенсивности снега (например, "Light snow" → column 3).
  • Особые случаи (например, "RA at OAT ≤ 0" → предупреждение).
Если правило возвращает "result", расчёт HOT прекращается, и это значение показывается пользователю.

Алгоритм работы системы с вашим JSON

  1. Получает METAR, парсит температуру, события, определяет интенсивность и контекстные флаги.
  2. Применяет event_index_rules (по приоритету). Если правило вернуло result – возвращает его.
  3. Если индекс не определён правилами, ищет по event_index (первая подходящая группа).
  4. Определяет temp_index – индекс первого диапазона из temperature_bands, куда попадает OAT.
  5. Применяет rules – они могут переопределить индекс или вернуть result.
  6. Пытается взять значение из table[temp_index][event_index].
  7. Если значение – объект с концентрациями, возвращает все ключи (для каждой концентрации своё время).
  8. Если значение отсутствует (null или нет такого столбца) – возвращает предупреждение.

Пошаговая инструкция для нового сотрудника

  1. Получите исходную таблицу (Excel/PDF). В ней есть:
    • Диапазоны температур (строки).
    • Группы погодных условий (столбцы) – их названия.
    • Значения времени на пересечениях, иногда с пометками.
    • Особые примечания (сноски) – например, «при OAT < -25°C HOT не определяется».
  2. Заполните temperature_bands – выпишите все диапазоны в порядке возрастания температуры.
  3. Заполните table – для каждой строки создайте массив ячеек. В каждой ячейке – объект с концентрациями. Если в таблице только 100/0, пишите { "100/0": "значение" }. Если есть 75/25 и 50/50 – добавляйте их. Для пустых ячеек ставьте null.
  4. Заполните event_index – сгруппируйте столбцы по событиям METAR. Если не уверены, скопируйте из существующего файла похожего типа.
  5. Заполните event_index_rules – выпишите все особые правила из сносок, которые влияют на выбор столбца. Если их нет – оставьте [].
  6. Заполните rules – правила, которые влияют на итоговое значение (температурные ограничения, интенсивность, особые случаи). Если их нет – [].
  7. Проверьте согласованность:
    • Количество строк в table равно temperature_bands.length.
    • Максимальный индекс столбца, используемый в правилах, не превышает длину event_index (если превышает – ничего страшного, будет предупреждение).
    • Все значения времени корректны.
  8. Сохраните файл с именем тип_жидкости.json (например, type_ii_cryotech.json, active_frost.json) в папку data/tables/ проекта.

Часто задаваемые вопросы

Вопрос: Что если у меня нет event_index и event_index_rules, а только таблица?
Ответ: Скопируйте event_index из похожего типа (например, для Type II или IV). Если группы событий отличаются, создайте свои, ориентируясь на названия столбцов в таблице.
Вопрос: Строки таблицы имеют разную длину – это нормально?
Ответ: Да, это допустимо. Если система попытается обратиться к столбцу, которого нет в строке, она вернёт предупреждение.
Вопрос: Как узнать, какие коды METAR использовать в event_index?
Ответ: Список возможных кодов приведён в файле data/config/metar_events.json. В event_index вы используете те, которые соответствуют столбцам таблицы.
Вопрос: Можно ли скопировать правила из другого типа?
Ответ: event_index часто одинаков для разных типов (например, Type II и IV), но rules и event_index_rules обычно уникальны для каждой жидкости. Их нужно заполнять на основе конкретной таблицы.

Пример готового файла (фрагмент для Type I)

{
  "temperature_bands": [
    { "min_inclusive": -3, "max_exclusive": 100 },
    { "min_inclusive": -6, "max_exclusive": -3 },
    { "min_inclusive": -10, "max_exclusive": -6 },
    { "min_inclusive": -100, "max_exclusive": -10 }
  ],
  "table": [
    [
      { "100/0": "0:11 - 0:17" },
      { "100/0": "0:05 - 0:08" },
      { "100/0": "0:18 - 0:22" }
    ],
    [
      { "100/0": "0:08 - 0:13" },
      { "100/0": "0:04 - 0:08" },
      { "100/0": "0:14 - 0:17" }
    ]
  ],
  "event_index": [
    ["FZFG", "FZBR", "IC"],
    ["-SN", "-SG"],
    ["SN", "SG"]
  ],
  "event_index_rules": [
    {
      "id": "br_freezing",
      "priority": 2,
      "when": { "events_list_has_any": ["BR"], "temp_lte": 0 },
      "then": { "event_index_override": 0 }
    }
  ],
  "rules": [
    {
      "id": "low_temp",
      "priority": 5,
      "when": { "temp_lt": -25 },
      "then": { "result": "CAUTION: No holdover time guidelines exist" }
    }
  ]
}
Проверка: После создания файла сравните его с существующими (например, type_i.json). Убедитесь, что структура и названия полей совпадают. При возникновении вопросов обращайтесь к разработчику.
